# TaipanStack v0.4.0 Release Notes

**Data de Lançamento:** 24 de Março de 2026

A versão `0.4.0` consolida o projeto introduzindo os pilares de resiliência corporativa. É o maior patch arquitetônico desenvolvido pelo time central que encapsula conexões externas defeituosas. O pacote expande a imunização nativa da ferramenta agregando camadas dinâmicas de Auto-aprendizado (Machine Learning base parameters) sobre Circuitos.

Consulte documentações interativas em: [Features (v0.4.0)](../features/adaptive-resilience.md).

---

### 🌉 Taipan Bridges
Um ecossistema modular plug-and-play que injeta resiliência por design nas ferramentas clássicas do ecossistema assíncrono.
* **Imports Bridge (`_imports.py`)**: Lazy initialization retornando encapsulamentos seguros baseados no *Result Monad*. 
* **HTTP Bridge (`http_bridge.py`)**: Cliente `SafeHttpClient` baseado em HTTPX. Proteção SSRF embarcada e conectada nativamente ao nosso mecanismo de repetição e disjuntor.
* **DB Bridge (`db_bridge.py`)**: Proxy protetor para Sessões ACID do SQLAlchemy e pools assíncronos do Redis garantindo reconexão sem gargalar *event-loops*.
* **Web Bridge (`web_bridge.py`)**: Implementa do zero o middleware de borda ASGI `TaipanMiddleware`. Limita chamadas (Rate Limit Token Bucket), expõe cabeçalhos restritivos nativos CSPs (Content Security Policies) e padroniza saídas HTTP Error JSON não-vaziveis.

### 🐕 Watchdogs (Active Monitoring)
Uma rede paralela de componentes dedicados à auto-observabilidade preemptiva.
* **HealthPinger**: Fica num cluster e tenta realizar pings curtos nas infraestruturas em background. Se não houver retorno, ele força o disjuntor de banco das rotas web a abrir preventivamente.
* **ResourceWatcher**: Fiscaliza `psutil` definindo janelas de alerta ou estrangulamento de requisições baseados no RAM e CPU % real.
* **ConfigWatcher**: Tira hashes criptografados do `.env` ou arquivo estático para sinalizar manipulações ou forçar reinicializações se os segredos mutarem.

### 🌌 Adaptive Resilience
Componentes dinâmicos de estabilização estrutural.
* **`AdaptiveCircuitBreaker`**: Subsitui tolerâncias estáticas numéricas. Este circuito monitora os sucessos e falhas em uma janela rolante e infla ou regride seu limiar de punição seguindo o quão degradada está a infra na hora.
* **`AdaptiveRetry`**: Monitora a efetividade do recuo exponencial para adaptar latências de *sleep* no motor `asyncio`.
* **`Bulkhead`**: Cria portões de limite de concorrência com fila máxima definida isolando cargas excessivas da pipeline HTTP.
* **`ResilienceOrchestrator`**: O novo objeto supremo desenhado sob o Builder Pattern que anexa Bulkeads -> Circuitos Adaptaveis -> Retrys Numéricos -> Timeouts Físicos -> Fallback Data em métodos `__call__` numa tacada só.

### 🛡️ Security / Performance / Quality (PR Integrations)
A versão `0.4.0` também absorveu e integrou com sucesso mais de 30 contribuições táticas de auditoria, consolidando:
* **Hardening Algoritmo Hash:** Reforçado `guard_hash_algorithm` contra potenciais mecanismos de bypass de entrada Enum (PR #318).
* **Auditoria de Código SAST:** Injetadas novas regras Semgrep customizadas (`.semgrep/taipanstack-rules.yml`) para identificar ativamente Insecure YAML loads e algoritmos de digestão criptográfica obsoletos (PR #326).
* **Mitigação de DoS:** Corrigido flagrante de vulnerabilidade onde um hash com tamanho massivo poderia transbordar a biblioteca Bcrypt, invocando o erro fatal de pilha `OverflowError` na validação de senhas (PR #307).
* **Sanitize Filename:** A velocidade de execução da rotina `sanitize_filename` foi significativamente otimizada para rotinas I/O intensivas (PR #322).
* **Type-Hint Estrito:** Todas as assinaturas utilitárias com classes nativas `Coroutine` / `Any` foram padronizadas para `Awaitable` garantindo o silêncio total do linter Mypy para devs (PR #323).
* **Testes de Borda:** Criados casos de testes adicionais prevendo os retornos contextuais de interrupção do Decorator `@retry` ampliando a estabilidade da biblioteca (PR #327).
* **Encerramento Massivo:** Encerramos de modo limpo `26 Pull Requests` obsoletas, englobando em sua essência bugs transitórios de Concorrência do Circuit Breaker antigo que causavam `Thundering Herd`. A arquitetura da recém introduzida `v0.4.0` encapsulou e bloqueou estas anomalias estruturais nativamente.
